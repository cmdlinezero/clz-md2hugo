# Deterministic Hugo generation

`clz-md2hugo generate` turns site-owned structured JSON into Hugo content using site-owned Go templates. The generator owns deterministic traversal, generated-file ownership, safe stale-file cleanup, atomic writes, and check mode. The site owns its schema, content semantics, templates, and output paths.

This boundary deliberately avoids built-in concepts such as Work, Mobile, Practice, products, courses, or certifications.

## Configuration

The default configuration file is `md2hugo.generate.json`:

```json
{
  "version": 1,
  "jobs": [
    {
      "name": "projects",
      "source": "data/projects.json",
      "template": "templates/project.md.tmpl",
      "output": "content/projects",
      "items": "projects",
      "path": "{{ .slug }}.md"
    }
  ]
}
```

Paths are resolved relative to the configuration file. `items` selects a top-level JSON array; omit it when the source itself is an array. `path` is a Go template evaluated once per record and must produce a relative path beneath the configured output directory.

The content template is also a Go `text/template`. It receives each JSON record as its dot value. The built-in template functions are `json`, `lower`, and `upper`. `json` is useful for safely emitting scalar or array values into YAML-compatible front matter.

## Commands

Generate content:

```bash
clz-md2hugo generate
```

Use another configuration:

```bash
clz-md2hugo generate --config path/to/generate.json
```

Verify committed/generated state without writing:

```bash
clz-md2hugo generate --check
```

Check mode exits unsuccessfully when any generated file would be created, changed, or removed, making it suitable for CI.

## File ownership

Every generated file begins with:

```html
<!-- Generated by clz-md2hugo; do not edit directly. -->
```

Cleanup removes only files carrying that exact marker. Human-owned files in the same output tree, including Hugo `_index.md` files, are left untouched.

## Source format

Version 1 intentionally uses JSON for structured input and configuration. JSON keeps the generator dependency-free beyond the existing CLI dependencies and provides a stable generic data model for arbitrary sites. Hugo sites remain free to use TOML or YAML elsewhere; consumers that adopt the generator should keep the generator-owned source in JSON unless a later generator contract adds another format explicitly.
